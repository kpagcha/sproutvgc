# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

sproutvgc is a competitive Pokémon dex (in the spirit of the Smogon and Showdown dexes): a Vue 3 + TypeScript + Vite SPA, deployed to GitHub Pages at `https://kpagcha.github.io/sproutvgc/`. It's organized in three areas (`src/lib/areas.ts`; the plan behind them is in the untracked `notes/competitive.md`): the **dex** (`/dex`), what exists in the regulation, with a list page and an entry page per category: Pokémon (`/dex/pokemon`, `/dex/pokemon/:id`: sprite, types, abilities, base stats, evolutions and forms, type matchups, moves), moves (`/dex/moves`, `/dex/moves/:id`), abilities (`/dex/abilities`, `/dex/abilities/:id`), items (`/dex/items`, `/dex/items/:id`) and conditions (`/dex/conditions`, `/dex/conditions/:id`: statuses, volatile effects, side and field effects, weather, terrains), plus the types (`/dex/types`, `/dex/types/:type`) and the type chart (`/dex/types/chart`); **Competitive** (`/competitive`), what players use and how it does: usage stats (`/competitive/usage`: the regulation's Pokémon by usage and how often they're brought, from the meta snapshot shown, with a pick between snapshots when several are active), speed tiers (`/competitive/speed-tiers`: a ladder of Speeds, the most used Pokémon at the Speeds their sets run, from the snapshot's `speeds`, with what could change them as chips of their own (boosts: the Speed items their sets hold, and every Speed ability each can have, however few of its sets run it), or every Pokémon once, at the benchmark picked (the fastest build, the slowest under Trick Room), and Trick Room, plus optional modifiers applied to everyone shown (Tailwind, Scarf, paralysis, stages); filters by type, ability and item (`?type=`, `?ability=`, `?item=`: an ability or item its sets run, each choice counting the Pokémon that pass the others); and the reader's own Pokémon (nature effect, Speed points, modifiers of its own, its Speed-doubling abilities by name (`doubled`, `doubled2`, `doublers` in `speedBuild.ts`), one needing a weather or terrain bringing it to the whole ladder, asked first while boosts show: boosts needing another leave the ladder, those it wakes count as their sets play, and the chip it's measured against, if one that left, gives way to the same Pokémon's unboosted) placed among them, with how often it moves first, weighted by usage (against those filtered), and, tapping a chip, the points it needs to move before it (`pointsToMoveFirst`); the speed pages' Pokémon pickers list by usage, with each one's rank, when there's a meta (`ranks`); whether boosts show is remembered under `sproutvgc.speedTiers.boosts`; the controls fold away (remembered), what's active then shown in short beside the heading; every choice and a picked row kept in the URL), the speed comparison (`/competitive/speed-tiers/compare`: yours against opponents, a pair side by side or, up to two a side, one under the other in the order they move with how each fares against each, or any Pokémon, up to 20, in speed order; the order logic in `src/lib/speedLineup.ts`) and tournament reports (still a "coming soon" placeholder, `ComingSoonView`); and **Tools** (`/tools`): a damage calculator and a team builder (coming soon), the type matchups page (`/tools/matchups`: a Pokémon's types defending and a moveset attacking, side by side on wide screens, with `/tools/matchups/def` and `/tools/matchups/atk` for one side) and a spaced-repetition type quiz (`/tools/quiz`). Each area has a page of its own listing its sections (`AreaView`; the dex's with the home page's search). Besides them: a home page, the front door to the whole site (the search, the reader's favorites and recently viewed, a card per area with its sections), a settings page (`/settings`: theme, language, and clearing everything the site has saved in the browser) and a credits page (`/credits`, linked from the footer), in English and Spanish. The header links to search (the home page, its search box focused), the three areas and settings, and under them the current area's sections (`AreaNav`; routes say which area and section they're in with `meta.area` and `meta.section`); on narrow screens the areas fold into a dropdown (`SectionMenu`).

## Commands

```sh
npm run dev         # dev server (base path `/`), also on the LAN for testing on a phone
npm run build       # marker check + vue-tsc type-check + production build, in parallel (base path `/sproutvgc/`)
npm run lint        # ESLint (lint:fix to autofix)
npm run format      # Prettier (no semicolons, single quotes, 120 columns)
npm run gen-data    # regenerate src/data/generated/ (add `-- --update` to repin the sources to their latest commits, `-- --update-smogon` for Smogon's month alone)
npm run check-text  # check the markers in our curated text (also part of `build`)
npm run bench-search  # time the search's matching over every language's names, at 1×, 10× and 50× the dex (`-- 1 100` for other scales)
```

The `justfile` wraps these for the user (`just dev`, `just dev-profile`, `just build`, `just preview`, which builds and then serves the production site at `http://localhost:4173/sproutvgc/`, `just gen-data`, `just check-text`, `just bench-search`); keep it in sync when scripts change.

There is no test suite, and none should be added. Verify changes with `npm run build` plus checking the app in the browser. The pre-commit hook (simple-git-hooks + lint-staged) runs `eslint --max-warnings=0` and Prettier on staged files, so any lint warning blocks a commit. CI (`.github/workflows/deploy.yml`) runs lint + build on every push to `main` and deploys, copying `index.html` to `404.html` so deep links work. `.github/workflows/usage-stats.yml` runs `gen-data --update-smogon` on the 2nd and 9th of each month and, when Smogon has published a new month, opens a pull request with it.

## Architecture

- **`src/data/types.ts`**: the Gen 6+ type chart, stored as a sparse attacker→defender map (pairs left out are 1×), exposed through `chart(atk, def)`. `TypeIcon`'s badges use the Bulbagarden Archives glyphs (`src/data/typeGlyphs.ts`), as do `CategoryIcon`'s move category badges (`src/assets/category-icons/`). `TypeId` is the canonical type key everywhere.
- **Generated data (`src/data/generated/`)**: written by `scripts/gen-data.ts`, never edited by hand (nor are the sprites it writes, below). It loads Pokémon Showdown's own code (through jiti) from a sparse checkout of its GitHub repo at the commit pinned in `scripts/sources.json` (cached in `node_modules/.cache`), applies the Champions mod and the rules of the VGC format for `VITE_REGULATION`, and derives availability from the regulation's legal Pokémon (an ability is available when one of them can have it, a move when one of them learns it and the game has it, an item when the game has it, a Pokémon when the format allows it). English names are Showdown's; every other locale's come from PokéAPI's CSVs, also pinned, at the language identifier `scripts/languages.ts` gives it (Spain's Spanish is `es`); nothing in the script is specific to a language. `scripts/overrides.ts` fills in by hand, per locale, the names PokéAPI doesn't have yet (it lags new releases), the ones it has outdated (renamed since), and names for entries the games don't name on their own (Showdown's per-mask Embody Aspects). Pokémon names are provisional: the species' official name plus the forme as Showdown labels it ("Garchomp (Mega-Z)", "Raichu (Alola)"), since PokéAPI's official forme names are patchy. The script stops and lists any name an entry of the regulation is missing. Bulbapedia is a place to check names by hand, never a data source: its text is CC BY-NC-SA. Use GitHub, not the npm packages (`pokemon-showdown`, or `@pkmn/dex`, `@pkmn/data` and `@pkmn/mods`): they ship the Champions mod but lag a regulation behind it, and the `@pkmn` ones have no format rules. The output is JSON, one entry per line: for abilities, moves, items and Pokémon, `<category>.json` (every entry and whether the regulation has it; for available abilities, moves and items also Showdown's `short` and `long` descriptions, verbatim, resolved for the Champions mod by its own `loadTextData`, which prefers the mod's text and falls back from either description to the other: the source our own descriptions are written from, never shown as is), `<category>.names.<locale>.json` (names of the available entries only, the only ones shown) and, for moves, items and Pokémon, `<category>.data.json` (what their pages show of each available entry: a Pokémon's types, base stats, abilities (in slot order, not marking the hidden one), forms and evolutions, its cell on the icon sheet; a move's type, category, power, accuracy, PP as Champions computes it, priority, target and flags; an item's kind and Megas; typed in `src/data/pokemon.ts`, `moves.ts`, `items.ts`); `pokemon.learnsets.json` (each legal Pokémon's moves, loaded on demand by `loadLearnsets`), `abilities.holders.json` (the legal Pokémon that can have each available ability, for its page), `conditions.json` (every condition something the regulation has causes, by Showdown ID, with those moves, abilities and items: declared on moves, or found in their code by `scripts/conditions.ts`), `available.json` (just the IDs of the available entries, per category, conditions included: the compact part the app needs at run time), `sprites.json` (the icon sheets' layout), `natures.json` (the natures' names in every locale, by Showdown ID, read through `natureName` in `src/data/natures.ts`), plus `source.json`, which records the commits, pages and format it all came from. **Sprites** come from Showdown's server (`scripts/sprites.ts`, through `sharp`): its Pokémon and item icon sheets trimmed to the regulation's entries, as lossless WebP, in `src/assets/sprites/` (drawn by `PokemonIcon` and `ItemIcon`, with `src/lib/sprites.ts`), and each legal Pokémon's gen5 sprite in `public/sprites/pokemon/` (`spriteUrl`; a Pokémon Showdown hasn't drawn yet has `noSprite` and its page shows its icon). They aren't versioned: `sources.json` keys their cache by the date of the fetch (`sprites`), and pins the commit of Showdown's client whose icon table places formes on the sheet (`client`). App code imports the full `<category>.json` files only with `import type` (for the ID types, at no bundle cost); Vite's `json.namedExports: false` keeps each JSON module a single `JSON.parse`.
- **`src/data/dex.ts`**: the dex's categories (conditions, moves, abilities, items, Pokémon, plus `group` for groups of effects) with their IDs (abilities, moves, items and Pokémon from the generated data; conditions from `src/data/conditions.ts`, the curated list of the ones with an entry of their own, each with its subkind and, when it differs, Showdown's ID: a condition is available when `conditions.json` has a source for it; groups list the IDs referenced so far), and `Ref`, the reference to an entry: a `kind` plus an `id`, as IDs are only unique within a category (Electric Terrain is a move and a terrain). Data mentions entries through the constructors (`move('soak')`, `condition('sun')`), never bare strings; `available()` hides what the current regulation doesn't have, from the generated data; nothing about availability is maintained by hand. Render a ref with `<DexRef :to>`, which is plain text until its category is registered in `PAGES` (its route's name, and the parameter that takes the ID: `id` unless given, `type` for the type pages; every category but groups is registered), and from then on a link. `src/data/typeinfo.ts` holds the interactions beyond the type chart, made of refs.
- **Meta (`src/data/meta.ts`)**: what players use, as snapshots from one source or another (Smogon's Showdown stats, the game's Battle Data, tournaments), each turned by an adapter in the generator into the one shape typed there and written to `src/data/generated/meta/` (`index.json` lists the snapshots, `<id>.json` holds each one's data by Pokémon, `loadMeta` loads it on demand). The only adapter so far is `scripts/smogon.ts`: Smogon's stats for the regulation's format over the month pinned as `smogon` in `sources.json` (`--update` moves it to the latest), a snapshot per rating cutoff (`smogon-1760`, `-1630`, `-1500`, `-0`), stopping on any name the dex doesn't have. The generator writes every snapshot it can; `VITE_META_SETS` in `.env` picks the ones the app shows, the first by default, so switching cutoff or source is a setting. With more than one, the reader picks one with `MetaPicker`, on any page that shows meta data, and it's the one every page shows from then on (`selectedSnapshot`, `selectSnapshot`, remembered under `sproutvgc.metaSet`; pages read it, and its data, through `useMeta`); on the dev server, a dev-only section of the settings page (`src/dev/MetaDevTools.vue`) overrides it in the browser (`setActiveSnapshots`, saved under `sproutvgc.dev.metaSets`), left out of production builds. The app never tells sources apart, only checks a snapshot's `capabilities` (`has`) and shows what's there; with none there's no meta. Every number shown is labeled with its snapshot (`metaLabel`), and what covers every player whatever the cutoff (`unweighted`: Smogon's brought counts) says so. The credits page credits the shown snapshots' providers. The plan and the sources are in `notes/competitive.md` and `notes/usage-stats.md`.
- **`src/lib/`**: pure logic with no Vue components. `typecalc.ts` (effectiveness, defensive profiles, coverage, multiplier formatting/CSS classes), `quiz.ts` (builds the quiz cards: "pick the multiplier" and "tick all types that apply"), `srs.ts` (SM-2 scheduling with Anki-style learning steps counted in answers rather than time; the deck is saved to localStorage under `sproutvgc.quiz.v1`), `motion.ts` (shared `SPRING`/`FADE`/`PRESS` animation settings), `stats.ts` (Champions' stats: base plus stat points plus 20, times the nature; HP plus 75, no nature; and the benchmarks that mark a stat's range, picked on the speed tiers), `speed.ts` (natures' effect on Speed, battle modifiers, and the table of the items and abilities that change it, with their multiplier, condition and the modifier that applies it (so a boost chip on the speed tiers counts a modifier its boost already is once, and leaves out what it can't be with: Unburden or an Iron Ball with a Choice Scarf on everyone), kept by hand: `npm run gen-data` lists any the regulation has, by Showdown's `onModifySpe`, that it lacks; the speed tiers turn the meta's `speeds`, Speed investments by stat points and exact nature, into Speeds with the base stats).
- **`src/views/`**: one lazy-loaded view per route (`src/router.ts`). Route `meta.titleKey` sets the document title; `App.vue` titles entry pages after the entry. Shared pieces: `MoveTable` (a sortable, searchable table of moves), `PokemonChips`, `RefInteractions` (an entry's type interactions, from `typeinfo.ts`), `SortHeader` with `useSort`. Entry pages title themselves with `EntryTitle`, whose star adds the entry to the reader's favorites (`useFavorites`, saved to localStorage under `sproutvgc.favorites.v1`), listed on the home page (`FavoritesPanel`) and, beside a page's way back (`App.vue`'s back row), those of its kind in a drop-down (`FavoritesMenu`: an entry page's category, the speed pages' starred setups; on phones, its star alone), and records the visit for the home page's recently viewed (`useRecent`, saved under `sproutvgc.recent.v1`, `RecentPanel`); both draw entries with `EntryChip`. Pages whose view is in their URL go among the recently viewed too, as they were left (their route's `meta.recent` says what counts as one visit: one per page, a comparison per pair; `router.afterEach` records them), drawn with `PageChip`. Those pages' setups can be starred too (`SetupStar` by their heading: what their route's `meta.setup` keeps of the URL, leaving out what's only a moment of it, such as the Pokémon found), several per page, listed among the favorites with `PageChip`. The Pokémon pickers (`PokemonPicker`) list, while their search is empty, the Pokémon picked lately in any picker with `recent` (every one so far), then the reader's favorite Pokémon, each group showing its first 8 with a link to all and folding away, then every Pokémon (`usePickerGroups`: the picks saved under `sproutvgc.picker.recent.v1`, the groups folded under `sproutvgc.picker.folded.v1`). The home route waits for the dex's names only when there are favorites or recent visits (`meta.dexNames` can be a function). The search (`useSearch`) finds the site's pages by name too (`pages`: an area's, or a section's by its label or title), on the home page and the dex's. List pages take the home page's search as `?q=`. The Pokémon list also takes filters by type, ability or move as `?f=` and `?fm=` (`src/lib/pokemonFilters.ts`): plainly a list, a Pokémon passing any of them, beside a type dropdown; in the advanced mode (on when the reader turns it on, remembered under `sproutvgc.pokedex.advancedFilters`, or when the URL's filters need it), groups of them, each joining its filters with AND or OR, the groups joined the same way, any filter negatable (`FilterGroups`, `FilterAdder`); its search's types, abilities and moves add one to the last group when clicked (`SearchResults` given `filters`), as Showdown's dex does. The moves list takes its category and flag filters as `?category=` and `?flag=` (`MoveTable`'s `category` and `flag` models), which a move's page links to. View state that should be shareable is kept in the URL query (matchup picks, the selected chart cell) and updated with `router.replace`. Long lists (the dex tables) render hundreds of components, so the ones in their rows are light: links are `AppLink`, a functional component around a plain `<a>` with its href resolved once and cached (`hrefOf`/`refHref`, `src/lib/links.ts`) and the router following it (`follow`), rather than a `RouterLink`; `PokemonIcon`, `TypeIcon`, `CategoryIcon`, `DexRef` and `DexText` are functional components too (render functions in `.ts` files, with their styles in `main.css`).
- **Descriptions (`src/i18n/en/<category>.ts`: abilities, moves, items, conditions)**: our own English text, curated from Showdown's (in `<category>.json`; conditions have none, so theirs are written from scratch and have no `source`), with "Pokémon" and markers for references to other dex entries (`{type:flying}`, `{move:taunt}`, `{ability:scrappy}`, `{item:ironball}`) that `<DexText :text>` renders as the entry's name (through `DexRef`) in the reader's language, linked once its category has pages; entries the regulation doesn't have are plain text. Each entry records `source`, a hash of the Showdown text it was written from, and `npm run gen-data` lists the entries whose source has changed since (to revise), the entries not described yet, and descriptions of entries the regulation no longer has. The files have no imports, so the generator can read them. Every other language translates ours in `src/i18n/<locale>/<category>.ts` (Spanish abilities so far), same shape and markers, with `source` the hash of the English it was translated from: `gen-data` lists, per language, the translations whose English has changed since and the entries not translated yet. The app loads one language's descriptions at a time, per category, on demand (`src/i18n/descriptions.ts`: `description(kind, id)`, falling back to English for one not translated yet; routes that show them list their categories in `meta.descriptions`). In text, an entry with a description shows its short one on hover. `scripts/check-text.ts` (part of `npm run build`, so CI runs it) checks every marker, in every language's descriptions, names an entry the dex has and the regulation has, through the app's own `dex.ts`; a new category of curated text needs adding to its `DESCRIBED` list.
- **i18n (`src/i18n/`)**: a small hand-rolled module, not vue-i18n. `en.ts` is the source of truth for `MessageKey`. Other locales are typed as `Record<keyof typeof en.messages, string>`, so a missing key is a compile error. Each locale also exports the official in-game names of the types (`types`), and of the conditions and groups (`names`, typed `Names`, so a missing one is a compile error too); conditions named after their move (`named: 'move'` in `conditions.ts`: Taunt, Tailwind) take its name, and generated categories (abilities, moves, items, Pokémon) get theirs from the generated data for every locale. `refName(ref)` (`src/i18n/refName.ts`) names any entry; the generated names load on demand, one locale at a time (`loadDexNames`), and routes that show dex entries set `meta.dexNames` so navigation waits for them (a new page with `DexRef` needs it too, or its names fill in a moment late). Use `t(key, params)` for `{name}` placeholders, `tSplit` to render a component (e.g. a type badge) in the middle of a message, `tSlots` for several, and `typeName(type)`. To add a language: create `src/i18n/<code>.ts`, add it to `LOCALES` (`src/i18n/locales.ts`, which the generator reads too) and `BUNDLES` (`src/i18n/index.ts`), give its PokéAPI identifier in `scripts/languages.ts`, and run `npm run gen-data`, which lists any names to add to `scripts/overrides.ts` (and, once `src/i18n/<code>/abilities.ts` exists, the ability descriptions left to translate; until then it shows the English ones) (`refName` picks up the new name files on its own). The type-check fails until each of those has the language.
- **Theming**: CSS custom properties in `src/styles/main.css`. Light is the default; dark comes from `prefers-color-scheme` unless overridden by `:root[data-theme]` (set by `useTheme`). The look itself (square ink-outlined surfaces, hard shadows, `TypeIcon`'s and `CategoryIcon`'s flat badges) is `src/styles/retro.css`, on top of `main.css`'s base; its rules start with `:root:root` so they win over components' scoped styles. `index.html` applies the saved theme before first paint. Multiplier colors are the `--m*-bg/fg` tokens, applied through `multClass()`. Components use `<style scoped>` plus the global tokens and utility classes.
- **Animation**: motion-v (`motion.*`, `AnimatePresence`, `layout-id`). Reuse the settings from `src/lib/motion.ts` so all animations feel consistent. `App.vue` wraps everything in `MotionConfig reduced-motion="user"`. Animations that run while a page renders (the page transition, the header's sliding highlight, `NavPill`) animate only `transform` and `opacity`, which the browser runs off the main thread: not motion's `x`/`y` nor a `layout-id`, which it animates on the main thread, so they stall while the page renders (`SPRING_WAAPI` is `SPRING` for the Web Animations API). Pages slow to render (the dex tables) show a skeleton until they're in (`usePageEntered`, `SkeletonRows`). On desktop they're also kept when left (`KeepAlive` over `KeptPage` frames, `src/components/PageFrame.ts`, listed in `KEPT` in `App.vue`), so coming back doesn't render them again; a kept page reads the route's query through `useActiveQuery`, which follows it only while the page is shown, not `useRoute()`. Phones' sliding pages (a `TransitionGroup`) can't hold a `KeepAlive`.
- **Tooltips**: the global `v-tip` directive (`src/directives/tip.ts`, tippy.js) replaces native `title`. `v-tip:group="..."` makes elements share one singleton tooltip that glides between them (used for table cells).
- **Env files**: `.env` (tracked) holds shared settings the build needs, such as `VITE_REGULATION`; `.env.development` (tracked) holds dev-server-only defaults; a gitignored `.env.local` is for personal overrides. Nothing secret goes in any of them, since `VITE_` values end up in the shipped app.
- **Profiling**: `VITE_PROFILE=true` (`just dev-profile`, or `.env.local`) turns on `app.config.performance` in dev, for Vue's per-component timings in the Performance panel. They inflate durations, so measure speed on `just preview` instead.
- **Dev-only**: the type quiz's dev tools (`src/dev/QuizDevTools.vue`, with `quizSim.ts` and `DevZone.vue`) and the settings page's meta snapshots (`src/dev/MetaDevTools.vue`) are loaded only when `import.meta.env.DEV` is true and are left out of production builds.

## Conventions

- Import from `src` using the `@/` alias.
- localStorage access is always wrapped in try/catch, with the app falling back gracefully; keys are prefixed `sproutvgc.`.
- Don't create or trace UI icons; the user picks icons themselves. UI icons come from Lucide (`@lucide/vue`), squared off by the `.lucide` rule in `main.css`.
